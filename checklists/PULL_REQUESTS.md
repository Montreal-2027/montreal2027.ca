# Pull Request Checklist

For feature branches and hotfix backports, open a pull request against `develop`. For hotfix branches, target `main-hotfix`.

- [ ] Commit and push your branch. Verify that the GitHub action has completed, then test the deployed change at [dev.montreal2027.ca](https://dev.montreal2027.ca).
- [ ] Assign the pull request to yourself.
- [ ] Add meaningful labels and add it to the **Tech** project.
- [ ] Link the related issue under **Development**.
- [ ] Describe the change and summarize how you tested it. Include screenshots for visual changes and call out configuration or data impacts where relevant.
- [ ] Document any setup, deployment, or data considerations in the pull request and issue.
- [ ] Request reviews from at least two other developers.
- [ ] Before a pull request can be merged, at least two reviewers must approve it and all automated checks must pass.
- [ ] Address all comments and requested changes made on the pull request. Only the commenter should resolve the comment.
- [ ] The Area Head makes the final decision on whether to merge the pull request, and will perform the actual merge.
